### 2. RFC #170 — Decommissioning (10') — Bill Stout

Filed 8/19, labelled `review`, assigned to @sarahnovotny and @imolloy, and already raised at WS4 main on 8/20 (§4 of [#171](https://github.com/cosai-oasis/ws4-secure-design-agentic-systems/discussions/171)). Two substantive reviews landed 8/20 and **both push the same way — make the stage terminal**:

| Reviewer | Position |
|----------|----------|
| Nicolai Nielsen ([@NicolaiNielsenTR](https://github.com/NicolaiNielsenTR)) | Supports the state; objects to the *name*. "Soft decommissioning" (assets and tokens retained, restartable) is not what practitioners hear in "decommissioned." Suggests **retirement**. |
| Imran Siddique ([@imran-siddique](https://github.com/imran-siddique)) | Supports stage 9; **would not land soft mode**. Proposes: kill switch = the control, quarantine = a restricted operational state, decommissioning = transition to terminal, decommissioned = terminal state. Anything reversible stays in Runtime/Maintenance. Also: change "identity deletion" → **authenticator revocation + identity tombstoning** (deleting the identifier breaks replay detection), and reframe the teardown receipt as a **disposition receipt** — the gate passes when every discovered asset has a *verified disposition* (revoked / deleted / crypto-shredded / retained-until / preserved-under-hold / exception), not when everything is deleted. Plus a forensic-order rule for incident-triggered retirement: quarantine → preserve evidence → revoke authority + descendants → dispose → receipt. |

**Decide:** drop soft mode from the RFC (recommend **yes** — it is the only contested part, and it is blocking a one-enum-value PR), then whether the ADLC phase text keeps a separately-named pause/quarantine state. Note the knock-on: `riskDecommissioningReversibility` is defined *as* the soft/hard collapse, so if soft mode leaves the RFC that risk's framing has to be rewritten before PR 3, not after.

Also on #170's open questions: **#3 — Reflection stage** ([secure-ai-tooling#401](https://github.com/cosai-oasis/secure-ai-tooling/issues/401)). Recommend keeping them decoupled; coupling delays a tag we need this week.
